# 2026-10-31

## compat 分支：Android 4.0 (minSdk 14) 重写

- 从 origin/pro 创建 `compat`，提交 843deb6，已推送 origin/compat。
- 实测确认：Compose 栈在 minSdk 14/21/23 均在清单合并阶段失败（material3-ripple 1.5.0-beta01 要求 24），
  因此不是改一行 minSdk 能解决的问题。
- 方案：删除 Compose UI，改为系统 View + Canvas；保留历法引擎、主题契约、存储与文案。
- 关键新增文件：
  - `PlainDate.kt`（替代 java.time，API 14 无 desugaring；且 desugaring 在 minSdk<21 强制 multidex）
  - `Plate.kt` / `PageArtwork.kt`（360x600 / 640x360 设计坐标，11 款主题绘制）
  - `PaperView.kt`（全屏页、Camera 翻页）、`ChooserView.kt`（Scroller 分页）
  - `StoreActivity.kt`（三栏商店、DragEvent 排序）、`StyleSheetDialog.kt`
  - `Ui.kt`（线程、预览位图缓存）
- 兼容处理：ImageDecoder→BitmapFactory+ExifInterface；AtomicFile→临时文件+fsync+rename；
  coroutines/Flow→Handler+监听器；setTint→ColorFilter；getDrawable→resources.getDrawable；
  矢量图用 generatedDensities 生成 PNG；补 mipmap-* 启动图标（API<26）。
- 保留但简化的行为：跨日动画统一为一次翻页；省略共享元素过渡与波浪进度。

## 选择页空白排查（真机 OPPO PHY110 / Android 15）

- 现象：滑到第 2 页起整屏只剩主题底色，缩略图/标题/圆点全无；进入全屏单页却正常。
- 根因：`ChooserView` 用 `View.scrollTo` 做分页。View 被滚动后 `onDraw` 的画布会整体平移
  `-scrollX`，而代码里又按 `i*width - scrollX` 再减一次，导致所有绘制落在屏幕左侧之外；
  `drawColor` 被 HWUI 优化成 RenderNode 背景色，所以只有底色可见。第 0 页 scrollX=0 时正常。
- 修法：分页用私有 `scroll` 字段，不再调用 scrollTo/scrollX。
- 附带：`PreviewCache` 单张预览 10MB 超过 24MB LRU，3 张永远挤掉彼此 → 每帧重渲染。
  预览位图宽上限 900px（约 5.8MB/张），三张可常驻，空闲不再重绘。
- 快滑会跳两页（位移取整 + 速度各加一页）；改为快滑固定从手势起点走一页。
- `values-v23/themes.xml` 的 `windowLightStatusBar` 在 Holo 黑状态栏下会让图标变深色不可见，已删。

## 选择页圆点与主题数不一致

- 圆点沿用 Compose 版「最多 9 个 + 滑动窗口」：11 个主题只显示 9 个点，
  且第 1–5 页窗口不动，看起来像「翻页圆点不变化」。
- 改为每个主题一个点（4dp，当前页 16dp 胶囊），总宽超出时自动收紧间距；
  实测 11 点行宽 261px、居中，第 4/11 页高亮位置正确。

## 设置面板与宽屏日期（18:9）

- 11 个主题逐个用 uiautomator 驱动样式面板：面板均能打开；翻页动画/交互式日历开关写入
  `theme_styles`；四个黄历的字色（原版/松绿/朱红）、节日版式、深色、定时（含时间选择器）、
  环境光自适应均生效；两个图片主题的填充方式与系统选图器可用。
- 发现并修复：全屏页原用 `GestureDetector`，横向滑动会被先判成长按 → 直接退出全屏，
  「交互式日历」实际不可用。改为自行记录 DOWN/UP，按位移判定滑动、按时长判定长按。
- 四个黄历的日期数字改为按「两侧竖排栏之间的可用带宽」计算：`dayNumber(day, bandLeft,
  bandRight, top, height, cap)`，留 56 设计单位边距，只允许比原来更窄，不允许变宽。
  16:9/18:9/21:9/横屏实测数字完整、左右留白均衡。
- 「回到今天」按钮从 28dp 抬到 72dp，避免压住页面底部农历行。
